# Writing stories

Stories here serve two readers. **People** browse them to see what a component looks like and when to use it. **Coding agents** read the same stories through Storybook's components manifest and MCP server: each story becomes a code snippet with a one-line summary, and the component's props come with their JSDoc. A story that is clear to an agent is clear to a person, so write every one for both.

These rules follow Storybook's own guidance for [writing stories](https://storybook.js.org/docs/writing-stories) and for [AI best practices](https://storybook.js.org/docs/ai/best-practices). `Button.stories.tsx` is the reference example.

## Where stories go

- One file per component: `src/components/genaro/stories/<Component>.stories.tsx`.
- Title `Components/<Group>/<Component>`, using the groups in `docs/README.md`: Actions; Layout and structure; Lists and tables; Forms; Feedback and status; Images and icons; App chrome and navigation; Overlays; App setup.
- Foundations pages are MDX in `stories/foundations`. Colour, spacing, radius and elevation, and icons are generated by `tools/foundations.mjs`; don't edit them by hand.

## The file

```tsx
import type { Meta, StoryObj } from "@storybook/nextjs-vite";
import { fn } from "storybook/test";
import { Button } from "@/components/genaro";
import guidelines from "../docs/Button.md?raw";

/**
 * Buttons trigger an action or navigate. A view has at most one primary
 * button, for its main action; everything else is the default secondary
 * button. Labels are a verb and a noun in sentence case ("Add vehicle").
 */
const meta = {
  title: "Components/Actions/Button",
  component: Button,
  tags: ["autodocs"],
  parameters: { guidelines },
  args: { children: "Add vehicle", onClick: fn() },
} satisfies Meta<typeof Button>;

export default meta;
type Story = StoryObj<typeof meta>;

/**
 * The view's main action. Use one primary button per view, so it's clear
 * what to do next; every other action stays secondary.
 * @summary the one main action in a view
 */
export const Primary: Story = {
  args: { variant: "primary", children: "Save vehicle" },
};
```

- **`component`** is required: the manifest reads the props and their JSDoc from it.
- **`tags: ["autodocs"]`** gives every component a docs page: description, primary story, controls, all stories.
- **`parameters: { guidelines }`** puts the component's full guidelines (`docs/<Component>.md`) at the bottom of its docs page.
- **The JSDoc above `meta`** is the component's description for people and agents: what it's for, when to use it, and which component to use instead when it's the wrong fit. One to three sentences.
- **`args`** hold realistic default content. Callbacks are `fn()` so the Actions panel logs them.

## The stories

- **One idea per story.** A story shows one variant, state or use: `Primary`, `Critical`, `Loading`, `WithIcon`. Not `AllVariants`. A story may render several items when they show the same idea (`Sizes` renders micro, medium and large).
- **Name it for the idea**, in UpperCamelCase: the name is what an agent searches for.
- **A JSDoc above every story that says why.** Lead with when or why you'd use it, in the first 60 characters; agents get a truncated description when there's no summary. Add `@summary` with a short phrase. Not "A primary button", but "The view's main action. Use one primary button per view…".
- **Prefer `args` to `render`.** Args show up in Controls and in the snippet. Use `render` only to compose several components (a `ButtonGroup` of `Button`s, a `Card` with content) and spread `{...args}` onto the component the story is about.
- **Start with the default.** The first story is the component with no special props.
- **States people meet:** loading, disabled, empty, error, long content where it matters.

## Content

- Use the Car Capital domain: vehicles, regs (`OY70 TZG`), stock IDs (`L-927`), leads, appointments, invoices, the master sheet. Not orders and products.
- Sentence case; buttons are a verb and a noun; UK spelling; money in pounds (`£16,419.00`).
- Realistic lengths. Show truncation or wrapping when the component has to handle it.

## Styling inside stories

- Genaro components and tokens only, as in the app: `var(--space-400)`, `var(--bg-surface)`, Genaro type classes. No hex, no pixel font sizes, no Tailwind palette colours.
- Layout glue (`display: flex`, gaps) is fine with tokens: `style={{ display: "flex", gap: "var(--space-200)" }}`.

## Interactive components

- Controlled components (`TextField`, `Checkbox`, `Tabs`, `Modal`…) need state. Use `useArgs` from `storybook/preview-api` so the story stays args-driven, or a small `render` with `React.useState` when that's simpler.
- Overlays (`Modal`, `Popover`, `Toast`) open by default in their stories, so the docs page shows them. When an overlay renders in a portal, give the story `parameters: { docs: { story: { inline: false, height: "480px" } } }` so it stays inside its frame on the docs page.

## The component's own JSDoc

The manifest also reads the component file. Give the component's JSDoc an `@import` line, so agents copy the right import (otherwise it shows the app's package name):

```tsx
/**
 * Triggers an action or navigates.
 * @import import { Button } from "@/components/genaro";
 */
export function Button(...)
```

Props should keep their JSDoc; it becomes the description in the props table and in the manifest.

## Checklist

- [ ] `component`, `title`, `tags: ["autodocs"]`, `parameters: { guidelines }`.
- [ ] A JSDoc on `meta`: purpose, when to use, what to use instead.
- [ ] One idea per story, named for it, with a "why" JSDoc and `@summary`.
- [ ] Realistic Car Capital content in sentence case.
- [ ] Tokens only; no hex, no hard-coded type.
- [ ] `@import` in the component's JSDoc.
- [ ] The Accessibility panel shows no violations.
