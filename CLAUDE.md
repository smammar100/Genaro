## Design system: Genaro
- UI is built with the Genaro design system in `src/components/genaro` (import from `@/components/genaro`). Read `src/components/genaro/README.md` once, and `src/components/genaro/docs/<Component>.md` before using a component.
- Use Genaro components for every control and layout block (Page, Layout, Card, IndexTable, TextField, Button…). Tailwind only for layout glue.
- Style only with tokens: `var(--bg-surface)`, `bg-(--bg-surface)`, `text-(--text-secondary)`, `rounded-(--radius-300)`; spacing via Tailwind's scale (p-4 = space-400). No hex colors, no Tailwind palette colors, no `dark:` color overrides — themes switch via tokens. The one exception is registration-plate yellow (`bg-plate`).
- Type follows the Fluid Functionalism scale (`src/lib/type-scale.ts`): six roles, each one size and one line height — display 24/30, title 16/22, subtitle 14/20, body 13/20, caption 12/16, micro 11/14. 24px is the largest size anywhere. Set text with a Genaro type class (`heading-lg` = display, `heading-sm`/`heading-md` = subtitle, `body-md` = body, `body-sm` = caption, `body-xs` = micro) or a role token (`text-display` … `text-micro`). No hard-coded type: no `text-xs`/`text-sm`/`text-[13px]`, no `leading-*` beside a role, no px font sizes in CSS (use `var(--fs-*)`/`var(--lh-*)`). Page titles and big figures are display; dialog and drawer titles title; card titles subtitle; control labels and body copy body; descriptions, badges, errors and table headers caption; counters and keyboard keys micro. Exceptions: reg plates, avatar initials, printed PDFs.
- Type rules from the same system (call 2026-10-25): three weights — regular 400 for text; medium 500 for component labels (buttons, tabs, badges, tags, filter pills, pagination: set by the components themselves, `font-medium` elsewhere); semibold 550 for headings, page titles, big figures, names in a row and selected items. Semibold is the heaviest weight anywhere: no bold until the user says so (`font-bold` renders semibold). Use `font-medium`, `font-semibold` or the Genaro `-semibold` classes; never set a raw `font-weight` or `font-[…]`. Two text colours: `--text` and `--text-secondary` (tones only for status); no opacity on text. No uppercase, no letter-spacing, no eyebrow labels. Codes (stock IDs, VINs, usernames) use `font-code` (Geist with even figures); only reg plates keep a plate face.
- Typefaces: Geist for all text and Geist Mono wherever a mono face is used (`font-sans` / `font-mono`, loaded by next/font in `app/layout.tsx`). Never Helvetica (or Inter) anywhere — not in font stacks, emails or PDFs. PDFs register Geist from `public/fonts/geist` (`src/components/pdf/fonts.ts`). Headings balance and paragraphs wrap pretty (globals); changing numbers get `tabular-nums`. Dense screens set `.type-compact` (the master sheet grid).
- The dark nav rail is the dark Genaro theme scoped to the rail (`data-theme="dark"`), not hand-picked colors.
- Sentence case, verb + noun buttons, one primary action per page, tone="critical" for destructive actions.
- Pages are Server Components where possible; navigate with `url` props; put callbacks and state in small `'use client'` components.
- Before finishing UI work run `node src/components/genaro/tools/audit.mjs src/app src/components` and fix what it reports.

## Storybook
- Storybook documents the design system: foundations (colour, typography, spacing, radius and elevation, icons) and every Genaro component. Run `pnpm storybook` (port 6006); `pnpm build-storybook` builds it.
- Stories live in `src/components/genaro/stories/<Component>.stories.tsx` and follow `stories/WritingStories.mdx`: one idea per story, a JSDoc on every story that says when and why (with `@summary`), realistic Car Capital content, tokens only. When you add or change a Genaro component, add or update its story and give the component's JSDoc an `@import` line.
- The colour, spacing, radius and icon pages are generated: after changing `styles/tokens.json` or `icons.ts`, run `node src/components/genaro/tools/foundations.mjs`.
- Agents can read the stories, props and docs through Storybook's MCP server at `http://localhost:6006/mcp` while it runs, or the manifests in a build (`storybook-static/manifests/*.json`).
- The app takes its UI only from what Storybook documents: Genaro components (`@/components/genaro`) and the app components that have stories (`App components/…`). Never import from `@/components/ui/*` (the old shadcn layer, being removed) and never write a raw `<button>`, `<input>`, `<select>`, `<textarea>` or `<table>` in app code; ESLint warns on both (errors once the migration finishes). If something you need isn't in Storybook, add it to Genaro with a story first.
- `src/components/genaro/stories/coverage.test.tsx` fails when a Genaro export has no story.
